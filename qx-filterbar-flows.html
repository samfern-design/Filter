What the prototype resolves

  • Three overflow strategies, one measurement. Switch Overflow to compare what happens to chips that do not fit: withdraw into All filters, wrap to more lines, or scroll on one line. The same fit arithmetic drives all three — only the response differs. Wrap is the one that costs a fixed row height. Scroll never withdraws anything, so the badge and panel stay in step with the bar — but the whole line moves together, which means the All filters trigger scrolls out of view. The spec pins that trigger precisely because it is the only guaranteed route to the full set, so the chevrons at both edges are carrying that weight now.
  • No result count on the bar. The spec asks for a live count adjacent to it; the number now lives in the table footer instead — and on the analyzer, in a footer added for the purpose. The aria-live announcement still fires on every filter change, so the count is still spoken even though it is no longer shown up there.
  • The badge counts what you set, not what exists. Zero filters, no badge. The spec defines it as the count of filters available elsewhere; that number is still in the telemetry as reachable only in panel, but the bar now answers "how filtered am I" instead of "how much is hidden".
  • The end state is the trigger and Clear. Once every chip is in the overflow menu the action group steps out too, so the narrowest row is two controls: the way back into the filters, and the way out of them.
  • The control row is the only row under menu and scroll. With the applied tray removed, state lives in the chip labels — and in the trigger, which takes the selected treatment whenever a set filter is off the bar.
  • Gated chips outlast ungated ones. Analyst rating is withdrawn last, after every ungated chip — watch the pills as you narrow.
  • Actions collapse before filters. On the Actions skin the group folds to one overflow button while all six chips are still showing.
  • The trigger width is reserved at its worst-case two-digit badge, so growing the count never forces a second pass.
  • One surface, two presentations. Pointer gets popovers and a drawer whose sections expand in place; touch gets a sheet that drills down. Switch Input mode to compare at the same width.
  • Expanding a section is not re-opening the panel. Entry transitions fire only on the render that opens an overlay, so a section expands without the drawer sliding in again.
  • The bar is one component across experiences. Options chain and analyzer are tabs on the same surface awaiting their filter sets — what changes per experience is the filter list and the result surface, not the bar.

Open against the spec

Label re-measurement. The spec caches intrinsic widths at mount and re-measures on locale or density change only — but a chip growing from Sector to Sector: Financials +2 changes width too. This prototype re-measures on label change and reports it in the telemetry; the spec should say so explicitly.

Applied state below the fold. Without the tray, a withdrawn filter that holds a value has no on-screen representation beyond the trigger's tint and count. The spec's own reasoning — applied state is what stops users reading a filtered table as the full universe — now rests entirely on that one affordance plus the result count. Worth a usability check at 360px before this ships.

Component name is still an assumption — this prototype treats the bar and the panel as one component with two skins.

What unifying the three settled

  • One component, four filter sets. Every tab runs the same bar — pinned All filters trigger, promoted chips in authored order, the same popovers on pointer and sheet drill-down on touch, one collapse algorithm, one live count. A tab contributes only its filters, its rows and its result surface: 14 filters for the screener, 8 for the chain, 4 for the analyzer, 8 for the matrix.
  • The matrix answers the parameter question differently. Its four controls are parameters, not filters — they change what is measured rather than narrowing a set — so instead of chips and a trigger it reads as a sentence: Showing average of true range per month in 2022. Every control is in the line, which is why it needs no All filters trigger, and the line wraps like prose rather than withdrawing anything. It is a real alternative to the chip bar for surfaces whose controls are all mandatory, and worth comparing side by side with the chain, where the same kind of parameters are chips.
  • Analysis carries the sentence. It is a named-metric picker with a description under each option — Total Return, Typical Daily Move, Volatility, % Up Days, Best Day, Worst Day, Total Volume — and each one implies a datapoint and a reduction. Picking Custom grows the sentence two more slots so you can set that pair yourself, which is the only case where the raw vocabulary surfaces. Descriptions in an option list are new to the engine; the DS's Select already supports the label-plus-sublabel template, so this is its filter-popover counterpart.
  • Choosing what to compare is not filtering. The universe and the compared symbols sit in their own row under the bar, as removable chips with a Compare picker — the reference's second row, and the one place the removable-chip pattern earns its keep. An empty set there means none rather than "no constraint", so clearing the row empties the matrix instead of showing all eight.
  • Daily means weekday. 252 date columns would not be a matrix, so daily frequency reduces by day of week — the effect a daily seasonality view exists to show. Day-of-month is the other reading; worth confirming which one the tool means.
  • One control can drive another. Choosing an Analysis sets the datapoint and the reduction behind it; choosing a Universe resets the compared symbols to that universe's members. That coupling had to be added to the engine — the spec assumes filters are independent.
  • Two filter kinds had to be added. A single-select choice (radio list with match counts, an explicit All at the top) and a slider, single or dual. A slider is the one control that cannot become a list of options, so its popover carries the control plus a live match count instead.
  • Expiry sits below the bar, at the team's direction. The spec puts navigation above the bar, so this is a deliberate departure: filters read first, then the expiry you are looking at. The strip still scrolls rather than collapses, and the Expiry chip filters which expiries it offers.
  • Display controls sit where each tool needs them. The chain's View is the last chip in the row — which also makes it the first thing withdrawn, worth deciding on deliberately. The analyzer's Table/Cards keeps its own slot beside the actions and never folds into the overflow. Neither is accented as applied, neither is touched by Clear all, and both stay reachable in the panel.
  • The panel reads in row order. Promoted filters first, in the order their chips appear, then everything that never made the bar under "More filters". Grouping by subject is gone — the trade is scannability across 14 screener filters for a panel that mirrors the bar exactly.
  • No per-option match counts. The spec asks for them inside every popover as the compensation for not seeing into a filter before opening it. They are out by decision, so the bar's live result count is now the only feedback a selection gets — worth watching in testing, on the chain especially, where a liquidity filter can empty the table in one click.
  • The menu does not animate in. Neither the drawer nor the sheet has an entry transition; only a drill step slides, and only when you move between levels. Nothing on the surrounding tool moves when the menu opens.
  • One control height across all three. 48px comfortable on every tab, so a sticky-header offset is a constant rather than a per-tool measurement.
  • Still open: the strategy accent colour is not in the Qmodii palette, and the chain's Near chip carries 41 options — the point where a searchable single-select starts to be the wrong control.
