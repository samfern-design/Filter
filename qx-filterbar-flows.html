What the prototype resolves

  • Filter inputs collapse, filter state wraps. Row 1 never wraps at any width; row 2 wraps and caps at two rows.
  • Gated chips outlast ungated ones. Analyst rating is withdrawn last, after every ungated chip — watch the pills as you narrow.
  • Actions collapse before filters. On the Actions skin the group folds to one overflow button while all six chips are still showing.
  • The trigger width is reserved at its worst-case two-digit badge, so growing the count never forces a second pass.
  • Applying a filter doesn't reposition neighbours — a chip grows in place; the withdrawal boundary moves, the order never does.

Open against the spec

Label re-measurement. The spec caches intrinsic widths at mount and re-measures on locale or density change only — but a chip growing from Sector to Sector: Financials +2 changes width too. This prototype re-measures on label change and reports it in the telemetry; the spec should say so explicitly.

Result count at the end state. With zero chips fitting, the row is the trigger plus the count. At 320px that still fits, so the count is never the thing that gets dropped. Worth confirming there is no narrower deployment.

Component name is still an assumption — this prototype treats the bar and the panel as one component with two skins.
